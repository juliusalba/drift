Quick start

Drift watches your Xcode builds, snapshots the screens, and tells you where they've drifted from your Figma design — without you having to eyeball a simulator.

  1. 1

    Link a project

    Click the menu bar icon → ⚙ Settings → Add project. Point it at your .xcodeproj and your Figma file.

  2. 2

    Run a check

    Press ⌘R from the menu or click Run. Drift builds, launches the sim, walks the flow, and captures screens.

  3. 3

    Read the drift

    Score is green / yellow / red at a glance. Click any screen to see the pixel diff against the Figma reference.

How it works

Drift is a loop. Every build triggers a capture; every capture triggers a diff.

flowchart LR A[Xcode build] -->|BuildWatcher| B(Simulator launch) B --> C[Walk flow via XCUITest] C --> D[Capture screens] D --> E{Compare to Figma} E -->|match ≥ 95%| F[Pass · green] E -->|85–95%| G[Warn · yellow] E -->|< 85%| H[Fail · red] F & G & H --> I[Menu bar status]

The whole loop runs headlessly — you don't need to touch the simulator unless something's wrong.

Linking a project

Drift needs two things: the Xcode project it should build, and a Figma file (or a folder of reference PNGs) to diff against.

Using Figma

  1. Generate a Figma personal access token at figma.com/settings → Personal access tokens.
  2. Paste it in Settings → Figma → Token. Drift stores it in the macOS Keychain.
  3. Drop your Figma file URL. Drift pulls frame thumbnails at device resolution.

Using static reference images

Drop a folder of PNGs named {screen-name}.png. Drift matches filenames to XCUITest screen captures.

Running a drift check

Three ways to trigger:

  • Automatic — any successful Xcode build fires a check
  • Manual — ⌘R or the Run button in the menu
  • CLI — drift-check --project ~/MyApp

Checks run in ~20–60 seconds depending on flow length. You'll see progress in the menu popover; the bar icon glows yellow while running.

Reading the report

Each run produces a per-screen match percentage. The overall score is the weighted average across screens, heavier on the ones you've marked as critical.

≥ 95% · Pass
85–95% · Warn
< 85% · Fail

Diff overlay

Red regions are pixel differences. Hover for likely cause — color off, text shifted, missing element. Drift ignores anti-aliasing and status-bar content by default.

Concepts

Baseline
The Figma frame (or static PNG) that the app should match. Updating your Figma updates your baseline.
Drift
Divergence between what shipped and what was designed. Expressed as a % of pixels that differ beyond a fuzz threshold.
Threshold
How tolerant the diff is. Default 2% — lower for launch screens, higher for data-heavy views.
Critical screen
A screen weighted more heavily in the overall score. Mark onboarding, paywall, and empty states as critical.
Flow
An XCUITest script that walks the app to the screens you want compared. Drift ships with a starter flow; you extend it per project.

FAQ

Why isn't my build triggering a check?

BuildWatcher tails Xcode's DerivedData. Make sure the project's DerivedData location is default, not custom. Custom paths require setting DRIFT_DERIVED_DATA in Settings.

My Figma token stopped working.

Figma tokens expire after 90 days of inactivity. Regenerate one and paste it into Settings — Drift replaces the keychain entry.

Can I exclude dynamic content (timestamps, user data)?

Yes — add a mask region in your Figma frame by naming a rectangle drift-ignore. Drift skips that region during diff.

Where are captures stored?

~/Library/Application Support/DriftBar/runs/{timestamp}/. Open via Settings → Reveal runs folder.
